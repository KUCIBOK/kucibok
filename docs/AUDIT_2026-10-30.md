| Constat | Statut |

| `settleTransaction` : un arrêt entre « processing » et « completed » laisse la transaction bloquée (pas de reprise, pas de remboursement, pas de rapprochement avec PayDunya). | ⚠️ |
| Abonnement : chaque paiement ajoute une ligne (période mensuelle repartant de « maintenant », pas de la fin en cours) ; pas d'annulation ni de rappel avant expiration. | ⚠️ |
| Essai expiré : curateur/advisor passent en lecture seule (402) — vérifier que l'UI affiche un message et renvoie vers le paiement. | ⚠️ |
| Statuts des tickets support : API `open/normal`, interface `ouvert/en_cours/resolu/ferme` → compteurs toujours à 0. | ⚠️ |
| Journal d'audit : `createLog` n'écrivait nulle part (`POST /log` ne faisait que `console.log`). | ✅ persisté dans `logs` (identité tirée du jeton) |
| `DeliveryTab` créait deux enregistrements (expédition + demande) et affichait « Données de test » en repli. | ✅ une seule création, texte retiré |
| `GET /profile/:id` crée une ligne `artists` à la volée, y compris pour un appel anonyme (écriture sur un GET). | ⚠️ |

## P2 — Sécurité (hors P0)

| Constat | Statut |
|---|---|
| Limitation de débit : repli **en mémoire**, non partagé entre instances serverless → inefficace sans Upstash Redis configuré. | ⚠️ configurer `UPSTASH_REDIS_REST_*` et vérifier en prod |
| CSP du front : `'unsafe-inline'` et `'unsafe-eval'` dans `script-src` annulent l'essentiel de la protection XSS. Passer à des nonces/hashes. `X-XSS-Protection` est obsolète. | ⚠️ |
| `VITE_API_KEY` est dans le bundle public : ce n'est pas un secret, ne pas s'en servir comme contrôle d'accès. | ⚠️ |
| 28 `console.log` dans l'API (règle CLAUDE.md : aucun en production), dont journaux de requêtes et `Visitor Tracked` avec corps complet. | ⚠️ |
| `sanitizeHtml` repose sur des regex maison : fonctionne par liste blanche et reconstruction de balises, mais mérite une revue (ou une librairie type `sanitize-html`). | ⚠️ |
| Téléversement d'image : extension prise du nom de fichier, pas de contrôle de taille/type côté client ; vérifier les politiques du bucket `artworks` (migration 006). | ⚠️ |
| Table historique `logidoo_alerts` : policy d'insertion `WITH CHECK (TRUE)` (retirée par la migration 009 — à vérifier sur la base réelle). La nouvelle table `logistics_alerts` n'a aucune policy (service_role uniquement). | ⚠️ |
| Mot de passe : minimum 8 caractères (vérification HIBP présente dans la CSP — confirmer qu'elle est appelée). | ⚠️ |
